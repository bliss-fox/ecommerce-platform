点击提醒可直接定位提案或订单，目标页重读当前记录和审计；已被其他会话决定的提案不能再次决定。选品、经济性、研究和内容页共享 SKU 选择，临时报价不修改已保存报价。跳转不会保存业务数据。切换数据空间保留页面位置，但清除旧对象、表单、预检和下载预览；需重新核对填写。

## 离线协作

进入“离线协作”，选择 1–3 个 SKU 和带时区报告时点，点击“开始离线评估”。任务仅评估当前已录入 SKU：使用保存报价评分，并对同候选全部报价比较单件假设经济性。目标说明仅作备注，不理解或执行任意自然语言任务。没有研究或事实时显示缺失，未知成本仍为未知；内容预览不保存草稿。

页面使用一个固定评估任务，不放只有一个选项的模板选择器。已有结果先展示主角色汇总及可用操作，实际角色状态、事件、来源修订与详细产物在“任务过程、角色结果与来源”展开；失败、未复核和来源失效仍直接显示。角色只调用代码白名单内的评分、经济性和模板工具，不读取素材文件或连接平台。运行成功与经营资格分开；阻断、反驳、场景不匹配及过期资料仍须处理。可生成 Markdown 报告，或携带 SKU 跳转“离线草稿”核对事实与素材。

展示、报告生成和跳转均重新读取相关来源基线；新增、删除和修订会使旧结果失效，停止报告下载和跳转并要求重新运行。报告下载是生成时的快照，之后发生的并发变更不会撤回已发送的文件。报告不含目标说明、提示词或真实模型用量；合成结果不能用于采购。

默认单步 30 秒、全流程执行 120 秒，无自动重试；失败保留明确标记的部分产物。取消和切换空间停止后续派发，迟到结果丢弃。线程不能强制终止，未结束的只读工作占用原资源名额；资源未释放时拒绝重跑，避免无限堆积。运行与报告仅在本地会话保存，刷新、断线或重启不保证恢复。M1 不提供任意 Python 插件沙箱、长期记忆或后台常驻经营。

## 环境与启动（Windows PowerShell）

历史阶段已在 Windows、Python 3.13.14 验证；M1/R1 使用现有虚拟环境 Python 3.14.6，Streamlit 1.66.1 / SQLModel 0.0.48 / Pydantic 2.14.1。项目要求 Python 3.11+，其余版本未验证；依赖锁保留原 Windows/Python 3.13 环境记录，本轮未重新锁定。安装依赖需要包源，应用与测试不需要外网或 API Key。

```powershell
Set-Location 'D:\AI_Dev\Project\电商'
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

依赖已安装后，可双击 `start.cmd` 启动并打开本机页面，使用 `stop.cmd` 停止本项目服务。也可在 PowerShell 运行：

```powershell
.\start.cmd -NoBrowser
.\stop.cmd
# 默认端口被其他程序使用时，启动和停止须使用相同的新端口。
.\start.cmd -Port 8502 -NoBrowser
.\stop.cmd -Port 8502
```

启动器精确核对本机监听进程的应用路径与参数；重复或并发启动复用同一服务，其他程序或另一项目占用端口时拒绝启动/停止。日志位于被忽略的 `local_data/service-端口.stdout.log` 与 `service-端口.stderr.log`。支持通过 `-PythonPath '完整路径\python.exe'` 使用另一个已安装依赖的环境。启动器不会创建虚拟环境或自动安装依赖；健康检查通过只表示 Streamlit 服务可响应，业务验收另见下文。Windows 进程检查受到系统/沙箱限制时须在可读取本机进程信息的终端验收；不会把检查失败当作端口空闲。

默认监听 `127.0.0.1:8501`。左侧选择“合成演示”或“真实数据”：前者使用 `demo.sqlite3.db` 并初始化随包合成数据；后者使用独立、初始为空的 `local.sqlite3.db`。不要把真实数据写入演示空间。真实空间拒绝 `fixture:` 引用（不区分大小写）；该检查不会自动扫描或清理已有数据，输入资料的真实性与合法使用依据仍需人工确认。数据库和 `.env` 不进入 Git。

Git 默认忽略本地数据库、环境变量文件、CSV、日志及常见用户素材；仅内置合成示例和模板 CSV 列入可跟踪例外。新增合成 CSV 需明确更新 `.gitignore`，请勿用真实数据覆盖例外文件。其他私人文件可放在已忽略的 `user_data/` 或 `user_materials/`。忽略规则不会移除已经被 Git 跟踪的文件，也不能防止强制添加；提交前仍需检查文件列表。

在“数据备份”主动生成并下载当前数据空间的 SQLite 快照；快照包含生成时已提交的全部表和审计记录。生成后对快照执行 SQLite 快速检查和外键检查，显示通过、发现问题或无法检查；检查通过不代表业务数据正确或恢复过程已验证。发现问题时仍可下载快照用于排查，并应保留原数据库。备份可能含私人数据，请自行选择安全的保存位置，数据更新后重新生成。生成与检查时快照暂存于应用会话内存，未自动同步；大数据库需要相应的内存空间。此入口不提供恢复或覆盖数据库操作。数据库结构检查失败时也可打开备份入口；数据库文件不存在或被占用时会报告失败。

初始化已有数据库时会检查已有业务表的必要字段、必填、主键、唯一和外键约束；不兼容时停止初始化并提示先备份，不自动迁移或修复。此检查不验证所有 CHECK 约束、字段类型或已有业务数据的正确性。

## 编辑、预检与确认

“数据管理 → 数据导入”统一提供候选/报价/研究与订单/费用/结算两组流程：选择文件 → 来源确认 → 预检与差异 → 确认写入 → 查看结果。页面可下载对应空白 CSV 模板；字段来自现有导入规范，不自动猜测列映射。P4 的支付口径、费用不含退款和整行本金结算仍须按上传文件分别确认；更换对应文件后确认失效。切换导入组或数据空间清除旧预检、来源确认及回执。

成功提交后显示实际批次、确认时间和增改/不变数，可直接查看本批修订。回执来自已提交批次，不能代表业务数据此后未变化；更换文件或新预检清除旧回执。页面重绘保留结果，刷新/断线/重启不承诺恢复会话。文件在导航后可能需重新选择及确认，永久批次可从修订历史查看。写入失败不展示成功回执，数据库异常不回显原始 SQL 或输入。

回执元数据无效或暂时读取失败时，页面显示错误并停止回执操作，不用零计数代替。读取失败不表示已提交数据回滚，请勿据此重复提交；读取恢复后页面重绘可重新核对原批次。P4 提交后的“按当前时点重新核对订单”始终进入报表，未选择订单时显示整体核对结果。

开始新预检会清除旧预检、回执与成功提示。预检读取数据库或保存失败摘要遇到数据库异常时，页面显示固定错误和重新预检指引，不展示底层 SQL 或异常原文，也不能继续确认旧结果。恢复后须主动重新预检、核对并确认，不自动重试或提交；此前已提交批次仍可从修订历史查看。手工编辑保留当前输入，未更换的 P4 文件保留来源确认，更换文件仍须重新确认。

初始化、导航核对或页面中尚未局部处理的数据库操作失败时，应用撤下当前页面的表单、结果和下载，只显示固定提示与“重新读取页面”；普通重绘不自动重试原操作，侧栏仍可进入数据备份。主动重新读取会清除未提交表单、旧预检与会话下载，并重读当前记录；保留空间、页面、子操作、报告时点及稳定目标 ID。请先核对已保存记录与审计，再判断保存或决定的结果：部分错误可能发生在提交后的刷新阶段，不代表原事务回滚。该处理仅针对 SQLAlchemy 数据库异常，不自动修复数据，也不把所有程序错误当作数据库故障。已有预检、回执及工作台分组的局部错误处理继续有效。

在“编辑与导入”页面选择实体进行手工新增或编辑，或分别选择一种或多种 P1/P2 CSV 文件；模板在 `data_templates/p1/` 和 `data_templates/p2/`。文本和引用使用多行输入，可查看并编辑 CSV 中保留的换行。两种方式共用验证、修订和审计规则。切换数据空间后须重新选择文件并预检。输入时间必须带时区，金额使用人民币十进制字符串，空白表示未知，零必须明确填写。SKU 的报价必须属于同一候选。

预检后检查新增、更新、不变、错误、缺失费用和前后值；填写不含个人信息的本地标识并点击确认，业务记录与成功审计才在一个事务中写入。手工编辑预检通过后内容锁定；需要更改时点击“修改并重新预检”。切换编辑记录或记录被其他会话修订时会清除旧预检；表单会刷新，未提交输入需重新核对填写。预检使用同一数据库快照，基线在预检后变化会拒绝提交。批次中的文件按序号区分，即使文件名相同或脱敏后相同也分别统计。失败预检保存文件哈希和脱敏错误摘要，不保存被拒绝的原始行；错误报告可下载。隐私检查只能识别部分常见风险，不能替代人工检查，请勿输入消费者身份、地址、凭证或秘密。

预检警告和变更超过 50 条时分页显示；请逐页核对，确认仍会提交整个通过预检的批次。错误批次仍不能提交，错误报告包含整批错误。

“修订历史”可分别选择成功批次和失败预检；成功批次的业务修订每页最多显示 50 条。全无变化的成功批次保留批次记录，但不会生成重复的业务修订。

按用户确认的 P1 口径，候选和 SKU 使用 `archived` 状态归档；报价保留历史，不提供删除。文件导入不删除记录。报价比较使用同一 SKU 的售价及其他假设：不满足一单一件的起订量或代发条件会明确提示；缺失费用不按零处理。修改 SKU 的报价须经过编辑、预检和确认，生成新修订。

## 研究与评分

“候选与报价”按当前候选展示详情及关联报价，左侧选择、右侧详情；窄窗口顺序排列。没有 SKU 的候选也可以查看。“SKU 经济性”只显示当前 SKU，分别列出已保存报价和临时比较报价；两者使用同一售价及费用假设，未知费用与场景不匹配保持明确标记。跨页继续携带 SKU，切换候选同步切换关联 SKU。

可直接编辑当前候选、指定报价，或进入当前 SKU 的“更换报价 / 编辑假设”。编辑页重新读取指定记录并清除旧预检和输入；修订号与修订时间在“版本详情”中展开。报价/假设/核验时间仍由人核对，导航不修改关联；变更须预检、核对差异并确认。评分先展示阻断和缺口，再展示分数，原规则与历史失败检查继续生效。

在演示空间的“编辑与导入 → CSV 导入”点击“预检合成研究示例”，核对并确认后加载 7 条研究、7 条关联和 15 条核验。此操作只针对演示库；真实库拒绝 `synthetic` 研究。也可逐项编辑，或上传三类 P2 CSV 同批预检。

进入“研究与评分”，选择报告时间、SKU 和同一候选的报价。页面显示固定权重的分项及贡献、10 个证据槽、去重和反驳来源、核验依据、输入修订、缺失项和阻断原因。总分仅在五维均完整时计算；只有 `ready_for_manual_review` 的结果进入排名。已归档或拒绝的候选及已归档 SKU 仍可查看评分，但不进入待评审排序；有失败阻断时仍优先显示阻断。排名使用 SKU 已保存报价；临时选择其他报价仅用于当前单项评分。单个 SKU 无法按所选时点评分时会显示原因，其他可计算的 SKU 仍会参与各自的结果分组。

历史失败不会因为过期或后续改成未知而自动解除；同一记录更高修订的有依据 `pass` 才能解除。每次页面评分从同一数据库读取快照计算，不回放历史快照；若当前相关记录的修订时间晚于所选报告时间，页面会拒绝该计算。报告时点可手工修改，也可点击“使用当前时点”；导入新修订后如时点过早，须更新时点再计算。合成评分只用于软件测试，不能据此采购。

## 离线内容草稿

页首“内容准备清单”集中列出事实和素材权利缺口，可展开已核实事实的依据与版本。在草稿页展开“从已核实事实填入标题与正文”，选择事实后点击“填入编辑表单”；这只改变未提交的标题/正文，仍须点击“保存草稿”。正文按选择顺序填入，可删减或排序。相关事实/素材变化后，旧草稿停止编辑与下载，需重新生成；已审核内容修改仍须先保存为草稿再审核。

进入“离线草稿”，先选择 SKU 和填写本地操作者标识。按需录入事实和素材：标记为“人工已核实”的事实须有证据索引及带时区的核验时间；第一人称使用经历应单独标为“使用经历”。素材只记录本地路径及权利依据，不会读取、上传或自动认定可发布；声明已有权利时须填写依据并确认其适用于该路径。修改已核实事实或依据时，必须重新核验并填写晚于该事实最近一次核验的时间；即使中间先改成待核实，也适用此规则；未修改内容和依据时，核验时间也不能早于历史已核实时间。

点击“生成离线草稿”，再编辑和保存。为保持事实可追溯，标题仅接受占位文字或一条已核实事实原文；正文每行须与已核实事实原文一致，可删除或调整顺序。拍摄清单可使用固定任务，或“拍摄已核实事实：”加事实原文；其他未确认内容放在待核实事项中。未核实事实和权利未知的素材会自动列入待核实清单，不能通过编辑清单移除。

草稿保存了事实和素材的版本快照，相关来源有新增或修改时须重新生成。其他会话修改正在编辑的事实、素材或草稿时，表单会刷新并丢弃未提交输入，须核对新版本后重新填写。修改曾经审核过的内容时，须先将修改后的内容保存为草稿，再重新审核；经过拒绝状态也适用此规则；`reviewed` 仅是内部状态。Markdown 预览与下载使用已保存版本，包含草稿标记、事实依据和素材核对清单。预览生成时检查来源；若其他会话在预览后修改了来源，请刷新页面后再下载。事实真实性、个人经历和素材权利仍由人核实；简易文本规则不能识别所有未经证实的说法。

## 订单成本与对账

从工作台定位订单，或在报表“查看订单来源”中选择订单，可查看分类成本及订单、费用、分摊、调整和结算的 ID、版本与依据。明细和金额来自同一次报告读取；费用池原始总额与本订单分摊分别呈现，未知费用和未记录结算保持未知。证据索引只展示，不自动读取文件或联网。

点击“导入有依据的修订”进入统一导入并携带订单，仍按整批文件校验，不自动筛选。返回后保持订单定位与原报告时点；提交后主动点击“按当前时点重新核对订单”才更新时点并重读数据。旧时点早于当前来源修订时仍拒绝计算，不回放历史快照。

在“订单成本与对账 → CSV 导入”选择订单、费用、费用分摊、成本调整和结算快照文件；模板位于 `data_templates/p4/`，可以跨文件同批预检。合成演示空间可以预检并确认导入 P4 合成示例；真实空间拒绝 `fixture://` 引用。导入前须人工确认订单支付金额符合契约口径、费用不重复包含退款，以及结算快照覆盖整条订单行本金。替换或移除相关文件后，须重新勾选相应的来源确认。软件无法从 CSV 自动证实这些来源事实；部分本金结算和混合来源数据不支持导入；结算截止时间不能早于付款时间。预检显示变化、缺失项和错误，只有填写本地标识并确认后才原子写入；重传按 ID 和修订处理，不按文件名判断。费用池必须在同一批次全额分摊，同一订单同一费用类别不能重复归属，调整与回收限制会连同现有记录重新检查。

“分摊建议”可将同次生成的费用池修订和分摊明细一起下载为 ZIP；解压后在 CSV 导入页同时选择两份文件，重新核对并确认。下载建议不会提交数据，数据库随后发生变化时仍须依预检结果重新核对。

“分摊建议”可对已保存的未分摊费用按所选订单数量计算整数分建议；下载费用修订和分摊两个 CSV 后，仍需在导入页面一并预检、确认。已存在同类成本来源的订单（包括金额未知的来源）不能重复分摊；界面会提示冲突。生成修订时系统时间须晚于费用当前更新时间；否则页面会提示核对费用时间和系统时钟。建议不会自动提交，最终仍须预检当前数据。有关合同来源与经营记录的真实性仍由人工核实。

下载的 CSV 保留原始文本以便核对或重新导入。若检测到文本以表格公式字符开头，页面会提示不要直接用电子表格软件打开；提示不改变文件内容，也不保证识别所有表格软件的解析行为。

“报表与核对”以带时区的 `as_of` 显示当前修订的订单明细、实际/估计/未知成本、贡献利润、累计到账、未反映退款及结算差异。实际成本完整和含估计成本的订单分别汇总净销售、变量成本与贡献利润，未知成本订单不计入这两组小计。SKU 汇总只加订单派生成本，列明实际、估计和未知订单数；任一订单成本未知时，该 SKU 的完整成本与贡献利润显示未知。SKU 汇总含订单行 ID，可与订单明细中的来源修订核对；存在未分摊费用时每行标记经营结果不完整。结算汇总显示差异净额、正负差额和待核对订单行数，净额为零不代表每笔已对平。报告不回放历史快照，若当前修订或相关事件晚于所选时间会拒绝计算；导入新数据后可手工更新报告或复盘时点，也可点击“使用当前时点”。订单明细、SKU 汇总与费用核对表可下载；原始已归属费用中费用池只计一次，没有记录的实际或估计类别显示“未记录”，不当作零金额。没有结算记录的订单显示“未记录结算”，不按零处理；未分摊费用和固定费用单列，贡献利润不是净利润。

## 本地提案与复盘

进入“本地提案与复盘”，选择已有候选、SKU 或订单作为目标，填写稳定提案 ID、变更前后快照、原因、至少一个证据索引及本地操作者标识。切换目标会清空未提交的提案内容；快照是人工录入的建议，不自动读取或修改目标数据；金额留空为未知，明确的零需填写 0。证据与数据的真实性仍由人工核实，请勿录入消费者身份或凭证。

在“审核与待办”组合选择提案状态、目标类型和 ID 筛选；ID 去首尾空白，区分大小写，按字面包含匹配提案 ID 或目标 ID，下划线不是通配符。列表每页最多 50 条，按创建时间及提案 ID 升序，时间以上海时区显示；先从当前页选择提案，再核对详情和审计。切换筛选会回到第一页；切换筛选、页码、所选提案或数据空间会清空未提交的决定。无匹配时不保留旧提案的决定或下载入口。其他会话改变列表后，超出范围的页码会收回最后一页；跨次翻页不保留历史快照，列表可能移动，仍须核对当前 ID。待审筛选下记录终态决定后，提案会离开当前结果，并显示决定已记录的提示。

审核时须填写决定依据和本地标识。待审提案可以批准、拒绝、取消或由人工标记到期；没有自动到期时间或后台任务。终态不可再次修改，意图变更须创建新提案。其他会话先记录决定时，旧表单不会提交，页面会提示查看当前状态和审计。提案与决定审计在同一事务写入；界面展开前后快照及证据列表，时间按上海时区显示。已批准提案可下载包含决定依据与审计编号的人工待办；如果批准审计缺失或不匹配，将拒绝导出。批准和下载均不会调用平台或证明外部操作已完成。

决定前检查创建审计，导出前检查从创建到决定的完整记录：创建快照、决定前后快照、当前提案、操作者和时间须一致，决定依据不能为空。审计缺失、重复、JSON 损坏或内容不一致时，审核页显示错误并停止该提案的决定和下载；可选择其他完整提案继续处理。请先从“数据备份”保留快照，再人工核对异常记录；应用不会自动补写审计。此检查只能发现记录之间的不一致，不能证明内容真实或防止数据库与全部审计被一致篡改。

“异常与复盘”基于 P4 当前修订生成异常列表和 Markdown 草稿，列出未知及估计成本、缺失结算、差异、未反映退款和未分摊费用等，并附数据时点及相关修订。报告不能回放历史快照，若来源晚于所选时点会拒绝生成；它不是完整经营审计或净利润计算。复盘是即时生成的草稿，不保存人工编辑历史。

## 源码打包与校验

使用标准库脚本按 `scripts/offline-files.txt` 的逐文件清单生成源码 ZIP，不递归打包工作目录；新增交付文件须显式加入清单。打包不会调用 Git 或读取业务数据库，不覆盖已有 ZIP 或校验文件。源码、说明、配置、测试、空白模板和合成示例随包交付；虚拟环境、Git、本地数据库、日志与用户资料不收录。

```powershell
.\.venv\Scripts\python.exe scripts/package_offline.py build --output user_data/xhs-seller-copilot-offline-20261102-interaction-r5.zip
.\.venv\Scripts\python.exe scripts/package_offline.py verify user_data/xhs-seller-copilot-offline-20261102-interaction-r5.zip
```

ZIP 内的 `OFFLINE-MANIFEST.json` 记录每个源文件的字节数和 SHA256，旁附 `.zip.sha256` 记录整个包的哈希。校验时须同时提供 ZIP 与同名 `.zip.sha256`，并使用对应版本随包的脚本及文件清单；校验不解压或执行包内文件。命令输出 JSON，失败返回非零码。相同文件字节在同一 Python/zlib 环境生成相同 ZIP；跨环境字节一致性未承诺。哈希用于完整性核对，不是签名或内容真实性证明。清单也无法识别有人写进已收录源码或合成示例中的真实秘密，交付前仍须核对文件内容。

校验支持构建器使用的 DEFLATE 和未压缩成员；其他压缩方法、损坏的压缩数据或无法解析的清单返回失败 JSON，不显示异常堆栈，不修改原包或解压文件。2026-11-02 的 A45 补强记录见 CHANGELOG。

解压到新目录后，使用已安装依赖的 Python 运行 `scripts/verify_offline.py`、pytest 和 ruff；首次安装依赖仍需要包源，ZIP 不含安装包。交付包不能替代数据库备份，也不能据源码校验声称业务或浏览器已验收。A44 实机补验仍待可可靠识别浏览器 URL 的工具环境完成；A45 的实际构建与解压复验记录见 CHANGELOG。

## 约束与后续

金额以整数分存储、Decimal 计算；未知成本不等于零。SKU 经济性是单件假设，P4 订单成本是整行金额。修改本地事实、素材、草稿或记录提案决定时，系统时间须严格晚于该记录的上次修订时间；时钟回退时需先核对系统时间。SQLite 初始化会先检查已有业务表是否缺少当前版本必需的字段，再增加 P1–P5 所需表；缺字段时停止并提示，不自动修改旧表。此检查不验证全部字段类型、约束或数据完整性，当前无通用模式迁移框架。依赖锁未跨系统或跨机器验证。

业务规则见 [数据契约](DATA_CONTRACT.md)，阶段范围和验收见 [任务清单](TASKS.md) 与 [验收案例](ACCEPTANCE_CASES.md)。P6 只读集成需另行授权。
